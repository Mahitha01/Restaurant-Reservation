# Team-Project-Phase 3

This phase was completed with the cooperation and discussion of Mahitha Kodali, Max Weinstein, Raphie Lubiniecki, Tommy Wei, Shawn Shu

To compile the code, first download the code to a local compiler, ideally Intellij or VsCode, then run the Server class followed by the Client class. Doing it in this particular order is the only way this will work because the Client connects to the Server and not the other way around. After running both classes, there will be a GUI window appearing on the screen. This is the main menu. There are three buttons on the main menu: login, create account, or delete account. By clicking on each of the buttons, the user will be led to a new page and prompted to enter their username, which is their email, as well as their password, if necessary.  The login, createAccount and delete pages all have a "go back" button that allows the user to return to the main menu. 

If the user is logging in, once they enter their email and password and click the login button, the server side checks the user's credentials, and a message will be displayed using simple GUI, indicating whether the user has provided the right credentials or not. If the user provided the right credentials, once the user acknowledges the message displayed, they will be able to look at the reservation page where they can view all their bookings, reserve for another day, view all available tables for every timeslot per day, and cancel their reservation. 

This phase, we focused on the GUI aspect of our code as well as storing and updating data that is consistent to all the reservations and cancellations. A few changes we made to the code from the previous phase is the details needed for making a reservation. So, we incorporated a table number stored in the booking class, created a database for storing tables at each operating hour of each day through HashMaps. We also created a text area called "Display Tables" that the user can scroll through that displays all the tables available at that particular time on that particular day. We incorporated tables so that the user can select a table from a drop-down menu that changes depending on the tables available and the partySize. We also enabled a time ticking feature at the bottom right that displays the current date and time of the users device which updates every second.

Apart from this, we incorporated real-time tracking by making the time be dependant on the date so if the user is trying to book for the same day, we made sure not to have times that have already passed to prevent users from reserving a table in the past. We also made the tables drop-down dependant on the number of attendees, so it is easier for the user to select a table that has a capacity higher or equal to the number of attendees. Note: The "Display Tables" text area doesn't depend on number of attendees because its purpose is for the user to be able to look at all available tables at any time and date they want. 

Our restaurant currently has 20 tables with capacities 2, 4, 6, 8 and 10. There are 4 tables per capacity. Along with this, we made the maximum limit of the number of attendees to be 10 since there's no limit on the number of bookings a user can make. The tables display always shows the user all available tables at the time and date they selected which get updated immediately after reserving or cancelling a reservation.

Please take note that since our project is about Reserving a table and most restaurants don't need a fee for reserving, pricing and variable pricing is not applicable to our project.
